# qi-graph · 图层

建在 [qi-kv](../qi-kv) 上的**属性图**：节点 / 有向边 / 标签 / 属性，邻接遍历、最短路径、
三元组模式匹配、JSON 导入导出。零 Rust，全部是 `.qi`。

```qi
导入 Graph::{开图, 图库};

变量 g: 图库 = 开图("社交.kv")
    .加节点("张三", "[\"人\"]", "{\"年龄\":30}")
    .加节点("李四", "[\"人\"]", "{}")
    .连("认识", "张三", "李四");
打印行(g.模式匹配("[{\"from\":\"?a\",\"type\":\"认识\",\"to\":\"?b\"}]"));
// [{"?a":"张三","?b":"李四"}]
g.关();
```

## 数据模型

| | |
|---|---|
| 节点 | `id`（字符串，调用方给或自动分配 `n1 n2 …`）、若干标签、属性（JSON 对象） |
| 边 | `id`（同上，自动 `e1 e2 …`）、类型、起点、终点、属性；**有向**，允许自环和多重边 |
| id / 标签 / 边类型 | 不能为空、**不能含 `:`**（它们是键的一段），违反的返回 0 |
| 一个图 | 一个 qi-kv 库文件；图句柄就是 qi-kv 句柄，本体层可以共用同一个文件 |

## 键空间

全部在 `g:` 前缀下，前缀 ASCII，段用 `:` 分隔：

```
g:n:<节点id>          {"id":..,"labels":[..],"props":{..}}
g:e:<边id>            {"id":..,"type":..,"from":..,"to":..,"props":{..}}
g:out:<节点id>        出边 id 的 JSON 数组
g:in:<节点id>         入边 id 的 JSON 数组
g:l:<标签>:<节点id>   "1"     标签索引
g:t:<边类型>:<边id>   "1"     边类型索引
g:meta                {"nodes":N,"edges":M,"next_id":K}
```

**邻接是每个节点一条值，不靠前缀扫。** qi-kv 的 `前缀列键` 是 O(全部槽) 的线性扫，
邻居 / BFS / 最短路径 / 模式匹配里带常量的一端全部走 `g:out:` / `g:in:`，一次遍历摸多少
节点就读多少条。前缀扫只留给三处全量操作：`按标签列节点`、`按类型列边`、导出 / 连通分量。

删节点会级联：它的所有出入边一起删，对端的邻接表和类型索引同步维护。测试里用
qi-kv 键数做账：删一个带 2 标签 4 条边的节点，键数正好少 5 + 8 条。

## API

自由函数是本体，`图库` 结构体的方法是一行转发，两种写法等价。写操作的方法返回自身
可以接着串；想知道成没成用自由函数（返回 1/0）。缺失返回空串或 0，不抛异常。
返回「列表句柄」的用完 `列表::删除列表`。

**开关**：`打开图(路径)`（打不开 -1）· `关闭图` · `图可用` · `开始批量` / `结束批量`（qi-kv 缓写）

**节点**

| 函数 | 说明 |
|---|---|
| `加节点(图, id, 标签JSON, 属性JSON)` | 1/0；id 已存在不覆盖，返回 0 |
| `新节点(图, 标签JSON, 属性JSON) : 字符串` | 自动分配 id，返回 id |
| `取节点(图, id) : 字符串` · `有节点` · `取属性` · `取标签` | |
| `改属性(图, id, 属性JSON)` | **合并**：同名覆盖、其余保留、类型保留 |
| `加标签` · `去标签` · `有标签` | |
| `按标签列节点(图, 标签)` | 列表句柄；走索引 |
| `删节点(图, id)` | 级联删边 |

**边**

| 函数 | 说明 |
|---|---|
| `加边(图, id, 类型, 起, 止, 属性JSON)` | 1/0；id 传空串自动分配；两端必须存在 |
| `新边(图, 类型, 起, 止, 属性JSON) : 字符串` | 返回分配到的 id |
| `取边` · `有边` · `删边` · `改边属性` | |
| `按类型列边(图, 类型)` | 列表句柄；走索引 |

**邻接与遍历**（`遍历.qi`）

| 函数 | 说明 |
|---|---|
| `出边(图,id)` · `入边` | 边 id 列表 |
| `出邻居(图,id[,类型])` · `入邻居` · `双向邻居` | 节点 id 列表，去重 |
| `出度` · `入度` · `度` | 多重边都算 |
| `广度遍历(图, 起点, 最大深度[,类型])` | 层序，起点第 0 位；最大深度负数不限 |

| `可达` · `连通分量数`（弱连通） | |

**查询**（`图查询.qi`）

| 函数 | 说明 |
|---|---|

**导入导出**（`图导入导出.qi`）：`导出JSON(图)` · `导入JSON(图, 文本) : 加了多少` ·
`导出到文件` · `从文件导入` · `节点数` · `边数` · `统计JSON`

> `匹配` 是 qi 的保留字（match），所以叫 `模式匹配`。

## 模式匹配

三元组列表，`?x` 是变量，其余是常量（节点 id / 边类型），边类型空串 = 任意：

```json
[{"from":"?a","type":"认识","to":"?b"},
 {"from":"?b","type":"住在","to":"成都"}]
```

带过滤：

```json
{"match":[{"from":"?a","type":"认识","to":"?b"}],
 "where":{"?a.props.年龄":{">":30}, "?b.labels":{"包含":"员工"}}}
```

- 变量可以在 `from` / `to` / `type` 任一位置，跨三元组同名必须一致，同一三元组里出现两次
  （`?a 认识 ?a`）匹配自环
- `where` 的键是 `?变量.props.字段` / `?变量.id` / `?变量.labels`，值是 `{运算符: 值}`，
  运算符 `= != > < >= <= 包含`（labels 还有 `不含`）。两边都是数字按数字比，否则按显示串比
- 求解是回溯：已绑定的一端顺着邻接表走；两端都没绑时走类型索引；类型也不定时走全边扫 ——
  **把带常量的三元组放前面**就避开了
- 结果顺序跟邻接表顺序（= 加边顺序）走，是确定的

## 导出格式

```json
{"nodes":[{"id":..,"labels":[..],"props":{..}}],
 "edges":[{"id":..,"type":..,"from":..,"to":..,"props":{..}}]}
```

键序固定，节点 / 边按首次写入顺序。从一份导出灌进空图再导出，文本逐字节相同。
导入是「加进去」：已有的 id 跳过，两端不存在的边跳过，返回真正加进去的个数。

## 性能（MacBook，1000 节点 / 5000 边，`测试/遍历_测.qi` 里的「规模」用例）

| | |
|---|---|
| 加 1000 节点（批量） | 22 ms |
| 加 5000 边（批量） | 177 ms |
| BFS 走遍全图 | 11 ms |
| 最短路径 n0 → n999 | 2 ms |
| 1000 次出邻居 | 11 ms |
| 两跳模式匹配 | < 1 ms |
| 连通分量（全图扫） | 24 ms |
| 关掉重开（qi-kv 重放） | 121 ms |

每加一条边是 5 次 qi-kv 写（边、两条邻接表、类型索引、meta），批量灌数据要开 `开始批量`。

## 命令行

```bash
qi compile 命令行/图工具.qi -o qigraph

qigraph 加节点 张三 --标签 人,员工 --属性 '{"年龄":30}'
qigraph 加边 认识 张三 李四                 # 打印分配到的边 id
qigraph 取节点 张三                         # 没有：不打东西，退出码 1
qigraph 邻居 张三 --类型 认识 [--入]
qigraph 遍历 张三 --深度 2 [--深搜]
qigraph 路径 张三 成都                      # 不可达退出码 1
qigraph 匹配 '[{"from":"?a","type":"认识","to":"?b"}]'
qigraph 标签 人 --条件 '{"年龄":{">":30}}'
qigraph 导出 > 图.json ；qigraph 导入 图.json
qigraph 统计 [--JSON]
qigraph --库 /data/知识.kv …               # 默认 $HOME/.qigraph.kv
```

## 已知边界

- 继承 qi-kv 的全部边界：数据集驻内存、没有 fsync、同一文件别开两个句柄
- 邻接表只存边 id，拿邻居要读边 JSON，邻居查询是 O(度) 次取 + 解码
- 没有加权最短路径，没有索引之外的属性查询（`过滤节点` 是标签索引 + 逐个看属性）
- 模式匹配两端都是变量且类型也是变量时会扫全部边
- `改属性` 合并时 null 值会变成空串（JSON 模块没有类型查询，靠取值结果推类型）
- 导出顺序是首次写入顺序而不是字典序；节点 id 只能用 JSON 里的字符串
